Security Architecture & Protection Overview

A transparent guide to our cryptographic implementation and threat monitoring engine.

🔒

1. Authenticated Encryption with Associated Data (AEAD)

Traditional file transfers often use unauthenticated encryption modes that remain vulnerable to bit-flipping attacks. CipherDrop implements authenticated encryption with a dedicated 128-bit authentication tag, guaranteeing both mathematical confidentiality and data integrity.

Unique Per-File Keys:

Each file upload generates a random 32-byte cryptographic salt and computes a unique 256-bit key via PBKDF2 (100,000 rounds). Keys are never shared across files.

Tamper-Proof Verification:

If even a single byte of the stored file is modified on disk, decryption immediately fails, auto-quarantines the file, and triggers a critical alert.

🛡️

2. Zero Plaintext at Rest

When an authorized user uploads a file, it is buffered strictly in volatile memory, encrypted directly, and stored solely as ciphertext (.enc). Server disk storage never holds unencrypted plaintext.

⚡

3. Continuous Anomaly & Threat Detection

Unlike passive cloud storage systems, CipherDrop proactively inspects file access patterns in real time:

  • Brute-Force Login Defense: Automatically locks user accounts after 5 failed password attempts and broadcasts an immediate alert.
  • Decryption Tamper Monitoring: Repeated failed decryptions or checksum mismatches automatically trigger emergency file quarantine to prevent data leaks.
  • Download Velocity Spikes: High-frequency mass download requests by any account are flagged in real-time.
  • Strict Recipient Authorization: Only designated recipients are cryptographically permitted to decrypt files. Non-recipient access triggers high-priority alerts.

Enterprise Standards Compliance

Built following Zero-Trust security principles, authenticated streaming cryptography, and NIST-recommended key derivation practices to ensure robust data confidentiality and comprehensive auditing.
